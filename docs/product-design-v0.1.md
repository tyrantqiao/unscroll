# Unscroll 产品设计 v0.1

日期：2026-10-04 · 状态：待评审 · 首发设备：OPPO Find X8 Ultra / ColorOS（实际版本待确认）

## 1. 产品定位

帮助用户在刷抖音、小红书时及时停下来。用户事先为应用设定边界，Unscroll 在到达提醒时长时提示，到达中断时长时进入冷静期，并可选择执行一次系统锁屏。

首版面向个人自用、无需 Root、本地运行的 Android 应用。无需账号，不上传应用使用记录。默认采用温和提醒 + 应用中断；系统锁屏需用户单独开启并通过设备能力测试。

成功标准：规则设置容易理解；到点能感知；冷静期能阻止立即继续刷；权限失效时明确告诉用户。

## 2. 核心使用场景

用户选择抖音：连续使用 15 分钟提醒，20 分钟中断，休息 5 分钟后允许重新开始。用户可为小红书设置不同阈值。另可设每日累计上限，例如 60 分钟，到达后限制至次日。

提醒文案：“已经刷了 15 分钟。还有 5 分钟，就到你设定的休息时间。”
中断文案：“这一轮到这里。休息 5 分钟，再决定要不要继续。”
避免羞辱、红色警报和成瘾标签；用平静而明确的语言提供边界。

## 3. MVP 范围

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 选择应用与规则 | 展示当前用户空间可启动的已安装应用；按实际包名绑定独立开关和规则 |
| P0 | 单轮计时 | 计时仅针对选定应用的前台使用 |
| P0 | 阶梯提醒 | 自定义提醒阈值与中断阈值 |
| P0 | 应用中断与冷静期 | 到点显示中断界面；冷静期重开应用仍拦截 |
| P0 | 权限与运行自检 | 展示哪些能力有效、哪些缺失 |
| P0 | 今日用量 | 展示累计时长、已完成休息次数、临时放行次数 |
| P1 | 可选系统锁屏 | 单独授权并完成测试后启用；失败降级为应用中断 |
| P1 | 每日累计上限 | 单应用累计预算；次日恢复 |
| 后续 | 跨应用共享预算 | 抖音与小红书合并计时，避免切换规避 |
| 后续 | 时段规则 | 睡前、工作时段差异化阈值 |

首版不做儿童监护、远程控制、云同步、排名或内容识别。个人用户可撤销权限或卸载，不能宣传为不可绕过的系统封禁。

## 4. 信息架构与页面

底部三个入口：今日 / 规则 / 设置。

### 今日

顶部显示保护状态：“保护运行中 / 仅统计 / 需要修复”。主卡显示今日受控应用累计使用与当前规则。应用卡显示今日用量、单轮进度和剩余时间。点击卡片进入规则编辑。权限缺失时，顶部展示具体修复入口，不显示虚假的正常状态。

### 规则编辑

应用名称 → 计时方式（单轮 / 每日）→ 提醒时间 → 中断时间 → 冷静期 → 中断方式（休息页 / 休息页 + 系统锁屏）→ 临时放行设置 → 保存。

默认：15 分钟提醒、20 分钟中断、5 分钟冷静期、每日可临时放行一次 3 分钟。阈值可手动输入或步进调整。提醒阈值必须小于中断阈值；开启每日上限后，单轮阈值与每日预算分别展示。

### 提醒

优先显示简短可感知提示，按钮“现在休息”和“继续到 20 分钟”。继续不会重置计时。通知权限缺失时明确提示通知不可用；无障碍提醒界面需要单独验证，不把通知送达当成可见提醒成功。

### 中断 / 休息

显示目标应用、触发原因、倒计时与“回到桌面”。到达中断阈值立即结束该轮，不再提供普通继续按钮。可选锁屏模式先展示 3 秒提示，随后尝试一次系统锁屏；解锁后其他应用正常使用，重新进入受控应用时显示休息页，不循环锁整台手机。

“紧急使用”经过 10 秒等待和确认后允许一次 3 分钟放行，并显示今日剩余次数。电话、系统设置、紧急呼叫不作为限制对象。关闭保护的入口可用，避免误锁无法退出。

### 设置与适配助手

按能力展示：用量读取、实时识别、中断、通知、系统锁屏。每项都有状态、用途说明、跳转入口、返回后的复检。ColorOS 辅助步骤包含后台活动、自动启动（若当前版本提供）、电池优化、最近任务保留（若提供）。菜单名称和路径以真机版本确认，不写死所有机型通用路径。

## 5. 计时与规则契约

- 仅屏幕亮起且设备解锁、目标应用为当前主要交互应用时累计；后台音频、锁屏不计入。
- 离开应用立即暂停计时；60 秒内返回继续同一轮，不能靠短切换清零。
- 离开达到冷静期长度（默认 5 分钟）才重置该应用单轮。离开 60 秒至 5 分钟仍保留该轮用量。每日累计永不因切换或冷静期清零。
- 分屏、浮窗和画中画首版作为待验证场景；若无法可靠确定交互目标，标记统计可能不完整，不能暗示已完整覆盖。
- 每轮提醒只触发一次；中断状态持久化；同一事件不能叠加多个提醒或重复锁屏。
- 若离开期间已到时，不对当前其他应用执行锁屏；待重新进入受控应用时判定。
- 优先级：权限/运行异常 → 每日上限 → 单轮中断 → 提醒。多个规则同时命中只展示一张中断页。
- 冷静期使用单调时钟计算；持久化恢复同时校验时间与重启状态。无法可信恢复时显示“运行中断”，不编造历史计时。
- 每日按设备本地日历在 00:00 切换；跨午夜拆分累计，单轮不重置。调整时区/时钟需记录时间变化，禁止重复授予当天预算；实现前单独设计日期账本。
- 规则修改立即重新判定；若降低阈值至当前用量以下，保存前提示将立即触发中断。关闭或删除规则解除该规则的中断。

状态：未运行 → 计时 → 已提醒 → 中断/冷静期 → 可重新开始。任意状态丢失必需权限后进入能力降级，并记录覆盖缺口。

## 6. Android 可行性与架构建议

这是设计方向，尚未经真机验证。建议 Kotlin + Jetpack Compose；Room 保存规则、使用段与触发记录；DataStore 保存偏好；规则引擎独立于界面。

| 能力 | 候选实现 | 边界 |
|---|---|---|
| 历史用量 | UsageStatsManager / UsageEvents | 需要使用情况访问授权；事件有保留期；不能仅靠粗粒度聚合实现准时触发 |
| 实时应用识别 | 用户启用 AccessibilityService，结合使用事件校验 | 服务可能被关闭；仅处理包名/窗口变化，不读取聊天、页面文本或截图 |
| 中断展示 | 无障碍覆盖层与必要的返回桌面操作 | 普通后台 Activity 拉起存在系统限制；需验证 ColorOS 与导航手势行为 |
| 系统锁屏 | AccessibilityService.performGlobalAction(GLOBAL_ACTION_LOCK_SCREEN) | API 28 起提供；需检查可用系统操作、返回值与实际锁屏结果；失败时降级 |
| 每日统计 | 本地使用段累计 + 系统统计校验 | 服务缺口需显式标记，不能把不完整数据当作精准数据 |

无障碍服务不是免授权的后台通行证；不得自动开启权限、阻止卸载或伪装为辅助残障功能。若未来上架应用商店，需要另行确认当时无障碍服务披露与审核政策。首版不依赖设备所有者、Root 或 ADB 特殊授权。

实时提醒是否需要额外前台服务、采用何种合法服务类型，待 Android 目标版本与技术验证确定，不预先承诺永久后台存活。首次激活前先进行 60 秒测试规则，验证识别、提醒、中断和可选锁屏，再启用正式规则。

## 7. OPPO Find X8 Ultra 验证方案

首要确认实际 ColorOS、Android 版本、系统构建号、安装来源、通知与后台策略。官网型号信息可用于识别设备，不能证明某版本兼容。

| 测试 | 验收目标（目标值，不是实测结论） |
|---|---|
| 正常使用短阈值测试 | 60 秒提醒、90 秒中断；前台稳定时触发延迟不超过 3 秒 |
| 切换与熄屏 | 不误累计后台时间；短离开不清零；熄屏不触发重复动作 |
| 冷静期内重开 | 重新进入受控应用后 2 秒内展示休息页 |
| 系统锁屏开关 | 开启后一次锁屏；解锁后桌面与电话可正常使用 |
| 服务被关闭 / 权限撤销 | 恢复打开 Unscroll 后立即显示失效能力和修复入口 |
| 清理最近任务 / 省电 / 夜间待机 | 记录实际存活与恢复结果；失败即标记该构建不满足稳定保护 |
| 重启手机 | 首次解锁后恢复持久规则；恢复前的缺口明确显示 |
| 分屏 / 小窗 / 画中画 | 分别记录计时与拦截能力，未通过则列为不支持 |
| 临时放行与规则修改 | 放行额度不会因重开应用重置；时间到重新限制 |
| 跨日 / 改时间 | 用量不丢失、不重复发预算、不反复触发 |

单次计时误差目标：连续 20 分钟误差不超过 5 秒。耗电通过同条件开启/关闭对照测试后报告，设计稿不写未经测量的百分比。

## 8. 视觉设计

主题：“把时间拿回来”。暖白背景、深绿主色、薄荷绿状态、少量琥珀色提醒。中断页保持安静和留白，避免惩罚感。主要触控区至少 48dp，支持字体放大、深色模式和无障碍读屏；状态不能只靠颜色区分。

主视觉为简洁环形进度，展示真实用量。应用图标后续使用合法来源；当前原型使用文字标识。浏览器原型仅演示产品交互，不会读取手机应用或实际锁屏。

## 9. 实施顺序

1. 技术验证：在目标手机验证无障碍前台识别、提醒层、中断层、一次锁屏、清理后台后的恢复。任何核心验证失败先调整产品承诺。
2. MVP：规则、计时、提醒、休息页、权限自检、今日统计，完整走通抖音与小红书。
3. 增强：可选锁屏、每日上限、放行记录、ColorOS 向导与适配报告。
4. 后续：共享预算、时段策略、周报；以实际使用反馈决定。

待确认：实际系统版本；是否仅个人安装还是计划公开发布；偏好的提醒/中断阈值；是否接受无障碍权限。当前先采用个人自用和默认 15/20/5 分钟方案。

## v0.2 开发调整：通用应用管理

“规则”入口改为“应用”。展示当前用户空间有桌面入口的应用名称、图标、包名、开关与配置摘要。支持按名称或包名搜索、只看已开启、手动刷新；已开启项优先展示。每个应用独立保存提醒、中断、冷静期与锁屏开关，新应用默认关闭。关闭管控清除当前计时和冷静期，保留配置；重新开启从新一轮开始。

首页展示已开启应用，后台服务读取动态规则集合。旧版规则迁移保留原值。电话、系统设置、桌面与 Unscroll 展示为不可管控。查询范围限于当前用户空间的可启动应用，不保证后台组件、工作资料或应用分身覆盖。

实现采用 Android Launcher intent 查询和 manifest queries 声明，参见 [Android 应用可见性声明](https://developer.android.com/training/package-visibility/declaring)。浏览器原型仍为早期流程示意，Android v0.2 的实际应用列表为本次交付。
